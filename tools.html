00 · Before You Start

先明确一件事：你装的到底是什么

🔍
"VS Code 2026" 这个说法需要澄清

Visual Studio（简移 VS）是有大版本号的商业 IDE，Visual Studio 2026 是真实存在的版本， 和 Visual Studio 2022 一样按年份发布。
而 Visual Studio Code（简称 VS Code）没有 2026 这个版本—— 它是一个轻量编辑器，采用 1.x + 每月更新 的滚动版本策略，官方从不按年份命名、 网上说的"VS Code 2026"通常是"2026 年在用的 VS Code"的意思，直接装最新版即可。

💡
更重要的：编辑器 ≠ 编译器

新手最容易卡住的地方。VS Code 本身不能编译 C++， 它只是一个文本编辑器——你必须在它之外另外安装一个编译器（MSVC 或 MinGW-w64）， 再通过配置告诉 VS Code"用哪个编译器、加什么参数"。
Visual Studio 则是一个全家桶：编辑器 + 编译器 + 调试器 + 构建系统，装完开箱即用。

01 · Visual Studio 2026

Visual Studio 2026 完整安装教程

从下载到跑通第一个程序，照着做大概 20～30 分钟（主要时间花在下载）。

步骤 1 · 下载安装器

  1. 打开官网下载项 访问 visualstudio.microsoft.com/zh-hans/downloads， 找到 Visual Studio 2026 一栏。
  2. 选对版本：Community（社区版） 三个版本里，Community 对个人、学生、开源项目完全免费，功能对学习来说绰绰有余。 Professional / Enterprise 是给企业用的，别选。
  3. 点击"下载 Visual Studio"→ 选择 "Community 2026" 会得到一个几 MB 的引导程序（VisualStudioSetup.exe）、 它本身不是完整的 VS，只是下载器。

步骤 2 · 选择工作负载（最关键的一步）

⭐
这里选错，后面 90% 的"找不到编译器"都源于此

安装器打开后会出现「工作负载」标签页。你必须勾选，
👉 使用 C++ 的桌面开发（英文界面：Desktop development with C++）
它位于「桌面和移动」分组下。勾上之后，右侧会有一大堆默认组件被自动选中——那些都要留着。

这个工作负载帮你装了什么作用
MSVC v14x 生成工具（C++ 编译器与库）就是 cl.exe 编译器本体，最核心的一页
Windows SDKWindows 平台的头文件和库（windows.h 等）
C++ CMake 工具用 CMake 构建项目时必需
适用于 Windows 的 C++ AddressSanitizer内存错误检测工具，强烈建议保留
测试工具核心功能 / Google Test写单元测试用
用于 Windows 的 C++ Clang 工具（可选）多一个编译器可切换，初期可以不装

步骤 3 · 其他标签页

  • 单个组件：默认不用动。想装 Git 可以在这里勾「Git for Windows」。
  • 语言化：默认跟系统语言走，中文系统会自动装简体中文。
  • 安装位置：建议改到空间充足的盘，完整安装约 10～20 GB。

步骤 4 · 安装并重启

  • 点右下角「安装」，然后去喝茶。下载 + 安装通常 20～30 分钟。
  • 装完可能要求重启电脑，一定要重启。
  • 第一次启动会让你登录 Microsoft 账号——可以直接点"以后再说"，不登录也能用。
  • 主题选深色（Dark）对眼睛友好。

步骤 5 · 创建第一个项目

  1. 启动界面 → 「创建新项目」 也就是 Create a new project。
  2. 搜索框输入 "空项目"，选择「空项目」（Empty Project），语言选 C++
    ✓
    为什么推荐"空项目"而不是"控制台应用"

    「控制台应用」会生成一堆模板代码和预编译头（pch.h），对新手是干扰。 空项目什么都没有，你从零开始加自己的 .cpp， 对理解"一个程序由哪些文件组成"更有帮助。

  3. 填写项目名和位置 项目名建议用英文，例如 HelloCpp。 位置选一个好找的目录，例如 D:\Code\。 不要放在中文路径或桌面同步盘里，容易出奇怪的问题。
  4. 在「解决方案资源管理器」里右键「源文件」→ 添加 → 新建项 选「C++ 文件(.cpp)」，命名 main.cpp，点添加。
  5. 粘贴下面的代码，按 F5 运行 

#include <iostream>
#include <vector>
#include <string>

int main() {
    std::cout << "Hello, C++!\n";

    // 顺便验证一下 C++17 的结构化绑定能不能用
    std::vector<std::pair<std::string, int>> scores = {
        {"小 C", 100}, {"小 A", 98}
    };
    for (const auto& [name, score] : scores) {
        std::cout << name << " → " << score << '\n';
    }
    return 0;
}

如果弹出一个黑色控制台窗口并显示 Hello, C++!（恭喜，环境通了。） 如果窗口一闪而过，见下方报错排查。

推荐立刻改的几个设置

设置项路径推荐值为什么
C++ 语言标准 右键项目 → 属性 → C/C++ → 语言 → C++ 语言标准 ISO C++17 标准 (/std:c++17) 默认可能是 C++14，用不了结构化绑定、optional 等
警告等级 属性 → C/C++ → 常规 → 警告等级 /W4 把潜在问题提前暴露出来，学习阶段非常有价值

源码字符集 属性 → C/C++ → 命令行 → 其他选项 /utf-8 解决中文乱码的终极办法，强烈建议加上

02 · VS Code

VS Code 搭建 C++ 环境

再次强调（VS Code 是编辑器，不是编译器） 下面分两条路——路线 A 用 MSVC（和 Visual Studio 同一套编译器）， 路线 B 用 MinGW-w64（GCC 的 Windows 版，刷题党常用，命令和 Linux 一致）。

步骤 1 · 安装 VS Code

到 code.visualstudio.com 下载 Windows 版，安装时务必勾选"添加到 PATH"（默认已勾选）， 这样命令行里才能用 code . 打开当前目录。

步骤 2 · 安装编译器（二选一）

路线 A · MSVC已装 VS 就选它

如果你已经装了 Visual Studio 2026 并且勾了「使用 C++ 的桌面开发」， 编译器已经在你电脑上了，不需要再装任何东西——跳到步骤 3。

如果不想装完整的 VS，可以只装 Visual Studio 生成工具 （Build Tools for Visual Studio），同样勾选「使用 C++ 的桌面开发」工作负载，体积小很多。

路线 B · MinGW-w64刷题 / 跨平台

获取方式三选一，推荐前两个，

  • MSYS2（最推荐）：装完在终端跑 pacman -S mingw-w64-ucrt-x86_64-gcc
  • w64devkit：单压缩包，解压即用，无需安装
  • WinLibs：单个 zip，解压后抄 bin 目录加到 PATH

装完打开新终端验证：g++ --version 应输出版本号。

🧭
怎么确认编译器到底装好没有

打开一个新的 PowerShell 窗口（旧窗口不会重新加载 PATH），执行， 


# 如果你走的是 MinGW-w64 路线
g++ --version
gcc --version
gdb --version

# 如果你走的是 MSVC 路线
# 注意：cl.exe 默认不在 PATH 里，必须从「Developer Command Prompt」打开终端
cl

# 找不到命令时的排查：看看 g++ 到底在哪
where.exe g++
where.exe gcc

MSVC 特别说明：cl.exe 不在系统 PATH 里，因为它需要一堆环境变量。正确做法是从开始菜单打开 "Developer Command Prompt for VS 2026" 或 "x64 Native Tools Command Prompt for VS 2026"。 VS Code 的 MSVC 配置会自动调用一个脚本帮你设置这些变量，所以不必手动配。

步骤 3 · 安装 VS Code 扩展

扩展向扩展 ID作用必装，
C/C++（微软官方） ms-vscode.cpptools 代码补全、跳转、语法检查、cppdbg 调试器（MSVC 和 MinGW 都靠它） 必装
C/C++ Extension Pack ms-vscode.cpptools-extension-pack 上面那个 + CMake Tools + 主题等一整套 推荐
CMake Tools ms-vscode.cmake-tools 在 VS Code 里配置 / 构建 / 调试 CMake 项目 用 CMake 时必装
Chinese (Simplified) Language Pack ms-ceintl.vscode-language-pack-zh-hans 界面汉化 可选
CodeLLDB vadimcn.vscode-lldb 用 LLDB 调试（Clang / macOS 场景） Windows 上一般不需要

安装方式：左侧活动栏点「扩展」图标（四个方块），或按 Ctrl+Shift+X，搜索扩展 ID 即可。

步骤 4 · 准备一个测试项目

新建一个文件夹（例如 D:\Code\cpp-test）， 在里面创建 .vscode 文件夹，然后创建下面的 4 个文件、 路径里不要有中文和空格，这是新手最容易踩的坑。 


cpp-test/
├── .vscode/
│   ├── tasks.json              → 定义"怎么编译"
│   ├── launch.json             → 定义"怎么调试"
│   ├── c_cpp_properties.json   → 定义"代码补全去哪儿找头文件"
│   └── settings.json           → 编辑器行为（可选但建议）
└── main.cpp                    → 你的代码
03 · Configuration

四个配置文件，直接抄

下面给出 MSVC 版和 MinGW-w64 版两套。 按你实际用的编译器选一套复制，不要混着用。

📌
复制前必看：三处要改成你自己的路径
  • compilerPath：编译器的完整路径（用 where g++ 或 VS 安装目录查）
  • miDebuggerPath：调试器路径（MinGW 是 gdb.exe；MSVC 用 cppvsdbg 类型则不需要）
  • ${workspaceFolder} 不用改，它是 VS Code 内置变量，代表你打开的文件夹

3.1 tasks.json —— 定义怎么编译

版本 A：MinGW-w64（g++.exe）


{
  "version": "2.0.0",
  "tasks": [
    {
      "type": "cppbuild",
      "label": "C/C++: g++ 生成活动文件",
      "command": "D:/msys64/ucrt64/bin/g++.exe",
      "args": [
        "-fdiagnostics-color=always",
        "-g",                          // 生成调试信息（断点必需）
        "-Wall",                       // 打开常用警告
        "-Wextra",                     // 更多警告
        "-std=c++17",                  // C++ 标准，按需改成 c++20
        "${file}",                     // 当前打开的 .cpp 文件
        "-o",                          // 输出
        "${fileDirname}/${fileBasenameNoExtension}.exe"
      ],
      "options": {
        "cwd": "${fileDirname}"
      },
      "problemMatcher": ["$gcc"],
      "group": {
        "kind": "build",
        "isDefault": true             // Ctrl+Shift+B 的默认任务
      },
      "detail": "使用 g++ 编译当前文件"
    }
  ]
}

版本 B：MSVC（cl.exe）

MSVC 需要先执行 vcvars64.bat 来设置环境变量， 所以要用 cmd /c 包一层。把下面的路径换成你实际安装的版本号。 


{
  "version": "2.0.0",
  "tasks": [
    {
      "type": "shell",
      "label": "C/C++: cl.exe 生成活动文件",
      "command": "cmd",
      "args": [
        "/c",
        "\"\"C:/Program Files/Microsoft Visual Studio/2026/Community/VC/Auxiliary/Build/vcvars64.bat\" && cl /Zi /EHsc /W4 /std:c++17 /utf-8 /Fe:${fileDirname}\\${fileBasenameNoExtension}.exe ${file}\""
      ],
      "options": {
        "cwd": "${fileDirname}"
      },
      "problemMatcher": ["$msCompile"],
      "group": {
        "kind": "build",
        "isDefault": true
      },
      "detail": "使用 MSVC 编译当前文件"
    }
  ]
}
⚠️
MSVC 路径里的引号很容易写错

vcvars64.bat 的路径含空格（cmd /c 对引号的处理又很挑剔）。 正确写法是路径用双引号包住、整条命令外面再包一层双引号，也就是像上面那样 \"\"...\vcvars64.bat\" && cl ...\"。 如果一直报"命令语法不正确"，把 args 里的路径换成短路径，或者干脆改用 MinGW 路线。

3.2 launch.json —— 定义怎么调试

版本 A：MinGW-w64（gdb.exe）


{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "C/C++: g++ 调试活动文件",
      "type": "cppdbg",                      // 用微软 C/C++ 扩展的调试器
      "request": "launch",
      "program": "${fileDirname}/${fileBasenameNoExtension}.exe",
      "args": [],                            // 命令行参数，例如 ["input.txt"]
      "stopAtEntry": false,                  // true = 在 main 第一行就停下
      "cwd": "${fileDirname}",
      "environment": [],
      "externalConsole": true,               // true = 弹出独立控制台窗口
      "MIMode": "gdb",
      "miDebuggerPath": "D:/msys64/ucrt64/bin/gdb.exe",
      "setupCommands": [
        {
          "description": "为 gdb 启用整齐打印",
          "text": "-enable-pretty-printing",
          "ignoreFailures": true
        }
      ],
      "preLaunchTask": "C/C++: g++ 生成活动文件"   // ★ 调试前先执行这个任务
    }
  ]
}

版本 B：MSVC（cppvsdbg）

MSVC 用的是 Visual Studio 自己的调试引擎 cppvsdbg， 不需要写 miDebuggerPath，它自己去注册表里找。 


{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "C/C++: cl.exe 调试活动文件",
      "type": "cppvsdbg",                    // MSVC 专用调试器类型
      "request": "launch",
      "program": "${fileDirname}\\${fileBasenameNoExtension}.exe",
      "args": [],
      "stopAtEntry": false,
      "cwd": "${fileDirname}",
      "environment": [],
      "console": "externalTerminal",         // 成 "integratedTerminal"
      "preLaunchTask": "C/C++: cl.exe 生成活动文件"
    }
  ]
}
字段作用什么时候要改
type用哪个调试引擎MinGW → cppdbg；MSVC → cppvsdbg
program要调试的可执行文件一定要和 tasks.json 的 -o 输出路径一致
args传给程序的命令行参数刷题时最常用：写 ["< input.txt"] 做重定向（需结合 shell）
stopAtEntry是否在 main 入口暂停想从第一行开始单步就计 true
externalConsole是否用独立控制台需要 cin 输入时建议 true，集成终端有时无法输入
preLaunchTask调试前自动跑的构建任务必须和 tasks.json 的 label 完全一致，多一个空格都不行
🔴
最常见的报错："找不到任务 C/C++: g++ 生成活动文件"

这说明 launch.json 里 preLaunchTask 的字符串， 和 tasks.json 里 label 的字符串不完全一样。 把它们复制粘贴成完全相同的文本即可（注意中文冒号、空格、大小写）。

3.3 c_cpp_properties.json —— 只管补全，不管编译


{
  "version": 4,
  "configurations": [
    {
      "name": "Win32",
      "includePath": [
        "${workspaceFolder}/**"          // 自己项目里的头文件
      ],
      "defines": [
        "_DEBUG",
        "UNICODE",
        "_UNICODE"
      ],
      "compilerPath": "D:/msys64/ucrt64/bin/g++.exe",
      "cStandard": "c17",
      "cppStandard": "c++17",            // ★ 改成 c++20 就能用 concept / ranges
      "intelliSenseMode": "windows-gcc-x64",
      // MSVC 用户改成：
      // "compilerPath": "C:/Program Files/Microsoft Visual Studio/2026/Community/VC/Tools/MSVC/<版本号 /bin/Hostx64/x64/cl.exe",
      // "intelliSenseMode": "windows-msvc-x64"
    }
  ]
}
🎯
怎么找到 MSVC 的 compilerPath

在文件资源管理器里打开 C:\Program Files\Microsoft Visual Studio\2026\Community\VC\Tools\MSVC\， 里面会有一个以版本号命名的文件夹（形如 14.xx.xxxxx）、 进入它下面的 bin\Hostx64\x64\，找到 cl.exe， 把完整路径复制过来，记得把反斜杠 \ 换成正斜杠 /。

3.4 settings.json —— 让编码不再抽风


{
  // 保存时自动格式化（配合 clang-format）
  "editor.formatOnSave": true,

  // 默认文件编码：统一 UTF-8，中文才不会乱码
  "files.encoding": "utf8",
  "files.autoGuessEncoding": true,

  // 终端编码：Windows 下必须显式指定
  "terminal.integrated.defaultProfile.windows": "PowerShell",
  "terminal.integrated.env.windows": {
    "PYTHONIOENCODING": "utf-8"
  },

  // 关掉烦人的 检测到 #include 错误"
  "C_Cpp.errorSquiggles": "enabled",
  "C_Cpp.intelliSenseEngine": "default",

  // 保存时去掉行尾空白
  "files.trimTrailingWhitespace": true,
  "files.insertFinalNewline": true,

  // 自动保存
  "files.autoSave": "onFocusChange"
}
🧩
CLion / Visual Studio / VS Code 该怎么选？说句实在语
  • 纯新手、Windows：Visual Studio 社区版。少折腾，把时间花在语法上。
  • 刷题、写小工具：VS Code + MinGW-w64。轻快，配置文件一次写好到处能用。
  • 做正式项目、用 CMake：任一都行；CLion 的 CMake 体验最好（但收费，学生可免费申请）。
  • 结论：不要在这件事上纠结超过一大。能用哪个就用哪个，工具是可以换的。
04 · First Run

不依赖 IDE，用命令行跑一次

这一步非常重要。很多人用了几年 VS，却不知道"编译"这个动作究竟发生了什么、 手动跑一次，你就理解了整条链路。

步骤 1：写一个最简单的程序


// hello.cpp
#include <iostream>

int main() {
    std::cout << "Hello, world!\n";
    return 0;
}

步骤 2：编译它


# MinGW-w64 / Linux / macOS
g++ -std=c++17 -Wall -g hello.cpp -o hello
./hello

# 拆开看每一步在做什么：
#   -std=c++17   用 C++17 标准
#   -Wall        打开警告
#   -g           生成调试信息（否则不能断点）
#   -o hello     输出文件变 hello
#   hello.cpp    输入源文件 

# MSVC：先打开 "x64 Native Tools Command Prompt for VS 2026"
cl /std:c++17 /W4 /Zi /EHsc hello.cpp /Fe:hello.exe
hello.exe

#    /std:c++17   语言标准
#    /W4          警告等级 4
#    /Zi          生成调试信息（对应 g++ 的 -g）
#    /EHsc        标准异常处理模型
#    /Fe:hello.exe  指定输出文件向

编译过程其实分成四步

💭
理解这一点，你就超过了 80% 的初学者

编译器一次只处理一个 .cpp 文件（叫"编译单元"），把它们各自变成 .o / .obj， 最后由链接器把这些目标文件和库拼成一个 .exe。
这就解释了两件事：为什么"头文件里写函数实现"会导致"重复定义"（每个 .cpp 都包含它，都被定义了一次）， 以及为什么改了头文件，所有包含它的 .cpp 都要重新编译。

05 · Troubleshooting

新手最常撞的坑，这里已经有答案

现象 / 报错原因解决办法
控制台窗口一闪而过 程序运行完就退出，窗口随之关闭 ① 用 Ctrl+F5 而不是 F5；② 在 return 0; 前加 system("pause");（Windows）；③ 打断点后 F5
'g++' 不是内部或外部命令 g++ 不在系统 PATH 里，或者终端是安装前打开的 把 ...\bin 目录加进系统环境变量 PATH，然后重开终端；用 where g++ 验证
'cl' 不是内部或外部命令 MSVC 的环境变量没有设置 从开始菜单打开 "x64 Native Tools Command Prompt for VS 2026"，不要用普通 cmd
中文输出变成乱码 源码是 UTF-8，但控制台按 GBK 解读（或反过来） ① MSVC 加 /utf-8 编译选项；② 源码统一保存为 UTF-8；③ 在程序开头加 SetConsoleOutputCP(CP_UTF8);（需 <windows.h>）
VS Code 里到处画红线，但程序能编译 IntelliSense 找不到头文件 检查 c_cpp_properties.json 的 includePath 和 compilerPath；改完按 Ctrl+Shift+P 执行 "C/C++: Reset IntelliSense Database"
断点是灰色空心的，命不中 编译时没生成调试信息 检查编译参数：GCC 要有 -g，MSVC 要有 /Zi；并且确认用的不是 Release 配置
undefined reference to 'xxx'
LNK2019: 无法解析的外部符号		 函数只有声明没有定义，或定义所在的 .cpp 没参与链接 检查拼写、参数列表（const 也算签名的一部分）；确认相关 .cpp 已加入项目或编译命令
LNK1168: 无法打开 hello.exe 进行写入 上一次的程序还在后台运行着 关掉那个控制台窗口，或在任务管理器里结束进程，然后重新生成
找不到该任务 / The task ... cannot be found launch.json 的 preLaunchTask 和 tasks.json 的 label 不一致 把两个字符串改成一模一样（注意空格和标点）
程序运行中突然崩溃，无任何提示 很可能是数组越界 / 空指针 / 野指针 开 AddressSanitizer：GCC 加 -fsanitize=address；VS 项目属性里启用地址擦除器
改了头文件，程序行为没变化 增量编译没有重新编译依赖该头文件的源文件 执行「重新生成 / Rebuild」而不是「生成」；CMake 项目删掉 build 目录重来
fatal error: bits/stdc++.h: No such file or directory <bits/stdc++.h> 是 GCC 特有的，MSVC 没有 用 MSVC 时改成分别包含需要的标准头文件；或改用 MinGW-w64 编译
项目路径含中文，编译各种奇怪失贝 部分工具链对面 ASCII 路径处理不佳 把项目移到纯英文路径，例如 D:\Code\cpp
error: 'auto' ... only available with -std=c++11 编译器默认标准太老 显式加 -std=c++17，或在项目属性里改「C++ 语言标准」。
🛠️
遇到看不懂的报错，正确的求助姿势
  1. 先只保留第一条 error，把它的完整英文原句复制下来。
  2. 去掉路径和具体变量名，只留错误码和通用描述，例如搜 C2143 syntax error missing ';' before。
  3. 优先看 MSVC 错误码官方文档，它每条都会解释原因。
  4. 问别人时，贴出最小可复现代码 + 完整报错，别只发一句「我的代码报错了」。
